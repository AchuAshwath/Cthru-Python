## The Bug That Breaks Every Beginner

Consider what happens when evaluating this standard snippet:

```python
a = [1, 2, 3]
b = a
b.append(4)

print(a)
```

Developers taught that a variable is a "container holding a value" expect `print(a)` to output `[1, 2, 3]`. When the terminal outputs `[1, 2, 3, 4]`, they memorize a rule: _"Lists are mutable, numbers are immutable."_

That is not an explanation—it is a coping mechanism.

### What Actually Occurs in Memory:

1. `[1, 2, 3]` is allocated at heap address `0x10f440`.
2. `a` is an 8-byte pointer holding the address `0x10f440`.
3. `b = a` copies the **address**, not the list. Both `a` and `b` point to `0x10f440`.
4. `b.append(4)` modifies the memory block at `0x10f440` in place.
5. Evaluating `a` dereferences `0x10f440`. Because only one list was ever allocated in memory, `a` reflects the appended element.
