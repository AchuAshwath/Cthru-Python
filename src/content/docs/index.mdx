**Cthru-Python** is an open-source technical reference and visual execution guide dedicated to the internal mechanics of CPython—the reference implementation of the Python programming language.

Most programming documentation explains _what_ language constructs do syntactically. This guide explains _how_ the CPython runtime implements them at the level of operating system processes, memory layouts, reference counts, and bytecode instructions.

---

## The Motivation

Python is often taught through high-level analogies that obscure runtime behavior:

- Variables are introduced as "named containers" rather than pointers in a local namespace.
- Function argument evaluation is described using ambiguous terminology ("pass-by-object-reference") without referencing pointer dereferencing.
- Mutability is taught as an arbitrary set of rules to memorize rather than an intrinsic consequence of in-place heap allocation.

These abstractions conceal the underlying systems architecture:

```python
a = [1, 2, 3]
b = a
b.append(4)

print(a)  # Prints [1, 2, 3, 4]
```

When variables are understood as 8-byte pointer addresses stored within a call frame's `f_locals` array, and lists are understood as dynamically allocated `PyListObject` structs residing on the private heap, the behavior of the snippet above ceases to be a language quirk—it becomes a necessary consequence of memory addressing.

## Architectural Scope

This documentation examines CPython across four interdependent layers:

| Layer                       | Focus Areas                                                  | Key Components                                        |
| :-------------------------- | :----------------------------------------------------------- | :---------------------------------------------------- |
| **0. Hardware & Process**   | Memory addressing, 64-bit word size, virtual memory segments | CPU Registers, RAM, Process Call Stack, Process Heap  |
| **1. CPython Object Model** | Struct definitions, memory overhead, allocation              | `PyObject`, `PyVarObject`, `ob_refcnt`, `ob_type`     |
| **2. Compilation Pipeline** | Source translation, symbol tables, code generation           | Tokenizer, Abstract Syntax Tree (AST), `PyCodeObject` |
| **3. Virtual Machine**      | Bytecode execution loop, frame evaluation, scoping           | `ceval.c`, `PyFrameObject`, value evaluation stack    |
